# Вимоги до модуля Data-Migration

> Цей файл оновлюється по мірі розробки. Версія: 0.4

---

## Загальний опис

Odoo-модуль **`vd_data_migration`** — додаток для міграції даних між двома Odoo 18.0 інстансами через **JSON-RPC**.
Модуль надає UI-візард, в якому оператор налаштовує підключення до бази-джерела,
обирає модель, аналізує поля та запускає завантаження даних у поточну базу.

**Ключова особливість архітектури:** процес завантаження виконується на **фронтенді** —
JS Owl-компонент читає батчі записів з джерела через бекенд-проксі та передає кожен батч
на бекенд для запису в локальну БД.

## Функціональні вимоги

### FR-01: Додаток та навігація
- Модуль є **Odoo Application** (`'application': True` у маніфесті)
- У головному меню присутній один пункт — **«Міграція»**
- При виборі пункту меню відкривається **Wizard** (транзієнтна модель `TransientModel`)

---

### FR-02: Форма візарда — підключення до джерела
Налаштування **зберігається тільки в пам'яті візарда** (не зберігається між сесіями і не записується в БД).

| Поле | Тип | Обов'язкове | Опис |
|---|---|---|---|
| `source_url` | Char | Так | URL бази-джерела (наприклад `https://odoo-source.example.com`) |
| `source_db` | Char | Так | Назва БД на джерелі |
| `source_login` | Char | Так | Логін користувача на джерелі |
| `source_password` | Char | Так | Пароль (відображати як `password=True`) |

---

### FR-03: Форма візарда — вибір моделі

| Поле | Тип | Обов'язкове | Опис |
|---|---|---|---|
| `target_model_id` | Many2one → `ir.model` | Так | Модель у **поточній** базі |
| `record_count_source` | Integer | Ні (read-only) | Кількість записів у джерелі (після Аналізу) |
| `record_count_target` | Integer | Ні (read-only) | Кількість записів у поточній базі |

---

### FR-04: Таблиця полів (Field Mapping)

- Під полем вибору моделі — **таблиця полів** (`One2many`), видимі всі типи полів
- Кожен рядок таблиці містить:

| Колонка | Тип | Опис |
|---|---|---|
| `field_name` | Char (read-only) | Технічна назва поля |
| `field_label` | Char (read-only) | Мітка поля (`string`) |
| `field_type` | Char (read-only) | Тип поля (`char`, `many2one`, `one2many`, ...) |
| `source_exists` | Boolean (read-only) | Чи існує поле у базі-джерелі |
| `include` | Boolean | Чи включати поле у міграцію (`True` за замовчуванням; `one2many` → `False`) |
| `comodel` | Char (read-only) | Для Many2one/Many2many/One2many — назва пов'язаної моделі |

---

### FR-05: Кнопка «Аналізувати»

При натисканні виконати (бекенд):
1. Підключитись до бази-джерела через **JSON-RPC** (`POST /web/session/authenticate`)
2. Зберегти `source_session_id` у пам'яті візарда (TransientModel, не в БД)
3. Перевірити що обрана модель **існує у джерелі** — якщо ні, показати `UserError`
4. Отримати список полів моделі у джерелі через `fields_get()` (JSON-RPC)
5. Зіставити з полями поточної БД: заповнити `source_exists`
6. Заповнити `record_count_source` та `record_count_target`
7. Очистити таблицю полів і побудувати знову
8. Встановити `state = 'analysed'`

---

### FR-06: Кнопка «Завантажити» — Frontend-driven

#### Бекенд (`action_import()`):
1. Перевірити `state == 'analysed'` — інакше `UserError`
2. Скинути статистику (`stats_created = 0`, `stats_updated = 0`, `stats_errors = 0`)
3. Встановити `state = 'loading'`, `progress = 0`
4. Повернути оновлення форми (form reload)

#### Фронтенд — `MigrationProgressWidget.startImport()`:
Після виявлення `state = 'loading'` Owl-компонент запускає цикл:

```
offset = 0
loop:
  1. POST /vd_migration/fetch_batch
        { wizard_id, offset, limit: 100 }
        ← { records: [...] }   # бекенд-проксі читає з джерела

  2. якщо records.length == 0 → вийти з циклу (всі дані отримані)

  3. POST /vd_migration/process_batch
        { wizard_id, records: [...] }
        ← { created: N, updated: N, errors: N }

  4. offset += records.length
  5. Оновити прогрес-бар і лічильники
  6. Якщо this._stopped == true → вийти з циклу
```

5. По завершенню циклу — повідомити бекенд: `POST /vd_migration/finalize` із `{ state, stats }`
6. Показати підсумок у UI: створено / оновлено / помилок

---

### FR-07: Кнопка «Видалити»

При натисканні:
1. Показати **діалог підтвердження**: «Ви впевнені? Всі записи моделі `<назва>` будуть видалені з поточної бази.»
2. Після підтвердження — виконати `unlink()` для всіх записів обраної моделі
3. Оновити `record_count_target` → 0
4. Показати повідомлення про успіх

---

### FR-08: Обробка `many2one` полів (бекенд)

Значення Many2one з джерела приходить як `(source_id, name)`.

Алгоритм (виконується у `process_batch` на бекенді):
1. У відповідній пов'язаній моделі (`comodel`) шукати запис за `id` (search `id = source_id`)
2. Якщо знайдено — підставити локальний `id`
3. Якщо **не знайдено** — створити новий запис: `name = "<{source_id}>"`, мінімальні обов'язкові поля
4. Використовувати отриманий локальний `id`

---

### FR-09: Обробка `many2many` полів (бекенд)

Значення Many2many з джерела приходить як список `[id1, id2, ...]`.

Алгоритм:
1. Для кожного `source_id` — застосовувати алгоритм FR-08
2. Зібрати локальні `id`
3. Записати як `[(6, 0, [local_id1, ...])]`

---

### FR-10: Зупинка завантаження

- Кнопка **«Зупинити»** у прогрес-бар віджеті (видима при `state = 'loading'`)
- Встановлює локальний JS-прапор `this._stopped = true`
- Після завершення поточного батчу — цикл зупиняється
- Виклик `POST /vd_migration/finalize` із `{ state: 'stopped', stats }`
- Показати повідомлення: «Завантаження зупинено. Оброблено X / N записів.»

---

### FR-11: Прогрес-бар і кастомний віджет

- Відображати прогрес у реальному часі — **фронтенд-driven** (без polling)
- Реалізувати **кастомний Owl 2 віджет** (`MigrationProgressWidget`)
- Компонент є **оркестратором міграції** — виконує import-цикл
- Віджет показує:
  - Візуальна полоска (`0%` → `100%`)
  - Лічильник: `X / N записів`
  - Статус: `Завантаження...` / `Завершено` / `Зупинено` / `Помилка`
  - Кнопка **«Зупинити»** (FR-10) — видима під час завантаження
  - Фінальна статистика: `Створено: N | Оновлено: N | Помилок: N`

## Нефункціональні вимоги

| ID | Вимога |
|---|---|
| NFR-01 | Логування всіх JSON-RPC операцій через `_logger` (бекенд) |
| NFR-02 | Налаштування зберігається лише в пам'яті візарда, не записується в БД |
| NFR-03 | Підтримка Odoo 18.0, Python 3.10+ |
| NFR-04 | Батчинг: рівно 100 записів за один запит до джерела |
| NFR-05 | Обробка помилок: таймаут, недоступність сервера, невірні credentials, помилки запису |
| NFR-06 | Модуль без зовнішніх залежностей; JSON-RPC реалізований через `urllib.request` + `json` (stdlib) |
| NFR-07 | Логування результату міграції лише у файл/консоль (`_logger`), не в БД |

## Поза скоупом (v1)

- Міграція `ir.attachment` (файлів та зображень)
- `one2many` поля — відображаються в таблиці, але `include=False` за замовчуванням
- Синхронізація в реальному часі (webhooks)
- Scheduled job (автоматична міграція за розкладом)
- Multi-company підтримка
- Збереження налаштувань підключення між сесіями
- Журнал міграцій у таблицю БД
- Polling-ендпоінт прогресу (замінено на frontend-driven підхід)
